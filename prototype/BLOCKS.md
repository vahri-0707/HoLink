# Block catalogue refinement

Reference inspected: [the signed-in HoLink Page Editor](https://app.ho.link/blocks/header), including its Add a block catalogue and existing Dropdown properties, on 21 November 2026. The prototype uses the original Link, Content, Media, Social, Business, and Contact categories. This is a working selection of 15 types, not the entire production catalogue or its subscription system.

| Category | Block | Properties and audience interaction |
| --- | --- | --- |
| Link | Links | Title, URL, description; Classic, Cover, and Showcase displays |
| Link | QR Code | Title and destination; locally generated, scannable SVG |
| Content | Title & Description | Heading and body text |
| Content | Dropdown | Up to 8 editable questions/answers; native expandable answers |
| Content | Content Separator | Label; line, dots, or space |
| Media | Image Slider | Up to 6 image URLs, caption; previous/next controls and position count |
| Media | Music | Track, artist, direct audio URL; native play, pause, seek and volume |
| Media | Apple Podcast | Episode, show, URL; opens Apple Podcasts |
| Media | PDF | Title, URL and description; opens the document |
| Social | YouTube Video | Title, video URL and description; loads a YouTube player on request |
| Business | Calendly Booking | Title, Calendly URL and description; opens the booking page |
| Contact | Email | Label, address and subject; creates a mailto link |
| Contact | Phone | Label and number; creates a tel link |
| Contact | WhatsApp | Label, number and message; opens the chat |
| Contact | Location | Place and address; opens a map search |

All content types can be added to the page or directly to a Collection, edited, hidden, reordered, moved, removed, and restored with Undo. In a grid Collection, rich content spans both columns while standard link cards use the grid. Audience Preview keeps every full-width block aligned to the same edges.

## Atomic organization

| Level | Reused source |
| --- | --- |
| Foundations | `styles/tokens.css`: HoLink blue, neutral surfaces, Manrope, spacing, radii and elevations |
| Atoms | `src/components.js`: buttons, fields, radio/checkbox controls, badges, Regular Phosphor icons |
| Molecules | `src/block-content.js`: display options, item editor, preview cards and media controls |
| Organisms | Searchable block library, dynamic block form, Collection picker, live preview |
| Type definitions | `src/catalog.js`: names, categories, field definitions, icon mapping and defaults |
| Transactions | `src/model.js`: type validation, mixed moves, limits, visibility, order and history |

Primary buttons use solid HoLink blue `#004ED7`, with a darker solid hover color. Fill icons remain limited to sidebar, header, and Page Settings; catalogue and block icons stay Regular. UI layouts use CSS flex/grid and the existing spacing tokens. New catalogue states are implemented in the localhost prototype; the earlier Figma challenge screens remain the original Collection refinement deliverables.

## Compatibility and assets

The v1 upgrade keeps all original blocks, custom titles, settings, ordering and Collection membership. It adds five illustrative text/media/contact samples once, saves a backup of the original v1 document in localStorage, and marks the result v2. Existing v2 documents are never reseeded. Reset demo remains recoverable through Undo.

Original vector studies and the eight-second ambient audio sample are generated by `scripts/create-demo-assets.py`. Image and audio forms include sample buttons. Remote media uses direct URLs; uploads, third-party account connections, scheduling, and production publishing are outside this prototype. The sample film is credited to Blender Foundation. QR encoding uses vendored `qrcode-generator@2.0.4`; no QR URL is sent to an external generation service.

## UI review

Full review of the new catalogue, mixed content, dynamic forms, and Preview states; vanilla ES modules and the existing plain CSS system.

| Category | Evidence inspected | Result |
| --- | --- | --- |
| Typography | Catalogue, type labels, form fields, text/video/audio/QR cards | Shared hierarchy and bounded wrapping |
| Surfaces | Catalogue panes, display cards, mixed Collection and preview bounds | Shared edges, consistent padding and radii |
| Animations | New interactions and existing keyboard/reduced-motion rules | No new entrance or layout animation |
| Icons | All 94 SVGs and rendered selected block states | One Regular weight; requested Fill policy retained |
| Performance | Local assets, lazy media, native audio, on-demand video, cached QR SVGs | Media loaded only where needed |

| Severity | Location | Before | After | Why |
| --- | --- | --- | --- | --- |
| Medium | `src/catalog.js`, `src/app.js` | Add Block opened only a link form | Searchable catalogue with 15 working types | Content can be discovered by category or intent |
| Medium | `src/components.js` | All rows and candidates said Link | Type-specific label and Regular icon | Users can recognize content before selecting it |
| Medium | `src/model.js` | Only links could move into Collections | Atomic moves preserve all content types and settings | The organizing flow works with a realistic page |
| Medium | `src/block-content.js` | Every preview was a link card | Appropriate text, image, video, audio, QR, contact and disclosure views | Preview communicates the actual content and interaction |
| Medium | `src/app.js` | Newly added content could be outside the visible preview | Selected or added content is brought into view | Connects the list, properties and live preview |
| Medium | `server.mjs` | Audio duration and seek lacked file range support | Content length and valid byte-range responses | Native audio has usable duration and seeking |
| Low | `styles/app.css` | Gradient primary buttons | Solid brand-blue buttons | Follows the revised visual direction |

Rejected candidates: cloning paid-only upsell gates would obstruct the prototype task; autoplaying all media would distract from editing; adding entrance animations to routine selection would slow repeated actions.

Verification: `npm run check`, `npm test` (13 tests), `npm run check:icons` (94 SVGs). Browser checks cover search/empty state, global QR/Music creation, Content Separator creation directly inside a Collection and Undo, inline validation, audio playback/pause/seek (8-second local sample, seekable from 0 to 8), mixed move/Undo, gallery navigation, dropdown expansion, and YouTube player loading. All full-width mixed Collection cards measured 290 px with identical left/right edges. At 654 × 721 the catalogue, its panes and action row have no horizontal overflow. Computed styles on primary buttons show solid `rgb(0, 78, 215)` and `background-image: none`; catalogue icons remain Regular. Final captures: `screenshots/07-block-library-solid.jpg` and `screenshots/10-compact-block-library.jpg`.

Not verified: physical touch devices, assistive-technology use, a hardware QR scan, external booking/contact submission, or production upload integrations. No new motion was introduced; slow-motion animation recording was not performed. Verdict: **Approve for the local prototype scope**, with those verification boundaries.
